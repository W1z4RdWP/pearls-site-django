# Система аудита базы знаний

## Обзор

Система аудита автоматически логирует все операции создания, изменения и удаления в базе знаний. Все действия пользователей записываются с детальной информацией для обеспечения прозрачности и возможности отслеживания изменений.

## Логируемые операции

### Типы действий
- `create` - Создание объекта
- `update` - Изменение объекта  
- `delete` - Удаление объекта
- `copy` - Копирование объекта
- `move` - Перемещение объекта
- `mirror` - Создание зеркала урока
- `reorder` - Изменение порядка
- `actualize` - Актуализация урока

### Логируемые модели
- **Lesson** - Уроки
- **CategoryName** - Категории
- **LessonVersion** - Версии уроков
- **LessonCategoryMirror** - Зеркала уроков
- **Document** - Документы
- **Incident** - Инциденты
- **DictionaryTerm** - Термины словаря

## Структура записи аудита

Каждая запись содержит:
- **Пользователь** - кто выполнил действие
- **Время** - когда выполнено действие
- **Тип действия** - что было сделано
- **Объект** - над чем выполнено действие
- **IP адрес** - откуда выполнено действие
- **Старые значения** - данные до изменения (для update)
- **Новые значения** - данные после изменения (для create/update)
- **Дополнительные данные** - контекстная информация
- **Комментарий** - описание действия

## Использование в коде

### Автоматическое логирование в view

Для view классов используйте миксин `AuditLoggerMixin`:

```python
from .audit_logger import AuditLoggerMixin

class MyUpdateView(UpdateView, AuditLoggerMixin):
    model = MyModel
    
    def get_object(self, queryset=None):
        obj = super().get_object(queryset)
        # Сохраняем старые значения для аудита
        self.old_values = serialize_model_data(obj)
        return obj
    
    def form_valid(self, form):
        # Логируем изменения
        self.log_update_action(self.object, self.old_values, "Описание действия")
        return super().form_valid(form)
```

### Ручное логирование

Для AJAX функций и других случаев используйте функции напрямую:

```python
from .audit_logger import log_create, log_update, log_delete

# Создание
log_create(request.user, instance, request, comment="Создан новый объект")

# Обновление  
old_values = serialize_model_data(instance)
# ... изменения объекта ...
log_update(request.user, instance, old_values, request, comment="Обновлен объект")

# Удаление
log_delete(request.user, instance, request, comment="Удален объект")

# Специальные операции
log_copy(request.user, original_instance, new_instance, request)
log_move(request.user, instance, old_parent, new_parent, request)
log_mirror(request.user, lesson, category, mirror_instance, request)
log_actualize(request.user, lesson_version, request)
```

## Просмотр логов

### Через админ-панель Django

1. Перейдите в админ-панель Django
2. Найдите раздел "Builder" → "Записи аудита"
3. Используйте фильтры для поиска:
   - По типу действия
   - По модели
   - По пользователю
   - По дате

### Через API

#### Получение истории объекта

```
GET /builder/api/audit/history/?model_name=lesson&object_id=123
```

Параметры:
- `model_name` - название модели (lesson, categoryname, document и т.д.)
- `object_id` - ID объекта
- `limit` - количество записей (по умолчанию 50)
- `offset` - смещение для пагинации

Ответ:
```json
{
    "history": [
        {
            "id": 1,
            "timestamp": "2024-01-15T10:30:00",
            "user": "Иван Иванов",
            "action": "Обновление",
            "object_name": "Урок по безопасности",
            "comment": "Обновлен урок",
            "changes_summary": "title: 'Старое название' → 'Новое название'",
            "ip_address": "192.168.1.100"
        }
    ],
    "total_count": 15,
    "has_more": true
}
```

#### Поиск в логах

```
GET /builder/api/audit/search/?user_id=5&action=create&date_from=2024-01-01
```

Параметры:
- `user_id` - ID пользователя
- `action` - тип действия
- `model_name` - название модели
- `date_from` - дата начала (YYYY-MM-DD)
- `date_to` - дата окончания (YYYY-MM-DD)
- `search` - поиск по названию объекта или комментарию

## Примеры использования

### Отслеживание изменений урока

```python
# В LessonUpdateView автоматически логируется:
# - Какой пользователь изменил урок
# - Когда было изменение
# - Какие поля изменились (старые и новые значения)
# - IP адрес пользователя
# - Создание новой версии урока
```

### Отслеживание структуры категорий

```python
# При перемещении категории логируется:
# - Откуда и куда перемещена категория
# - Кто выполнил перемещение
# - Время операции
```

### Отслеживание актуализации

```python
# При актуализации урока логируется:
# - Создание новой версии
# - Ответственный за актуализацию
# - Период следующего обновления
# - Комментарий к изменениям
```

## Безопасность

- Записи аудита доступны только staff/superuser пользователям
- Через админку записи можно только просматривать (не редактировать)
- Удаление записей разрешено только суперпользователям
- API endpoints защищены проверкой прав доступа

## Производительность

- Используются индексы БД для быстрого поиска
- JSON поля для гибкого хранения данных
- Пагинация в API для больших объемов данных
- Возможность архивирования старых записей

## Настройка

Система работает автоматически после:
1. Выполнения миграций: `python manage.py migrate`
2. Перезапуска сервера

Дополнительных настроек не требуется.
