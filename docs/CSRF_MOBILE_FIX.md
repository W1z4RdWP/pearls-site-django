# Исправление проблемы CSRF на мобильных устройствах

## Проблема
При авторизации через мобильные устройства (телефон) возникала ошибка CSRF после успешной авторизации:
- Пользователь нажимает кнопку "Войти"
- Авторизация проходит успешно
- Но появляется окно с ошибкой CSRF (403)
- При этом пользователь уже авторизован в системе
- На компьютере проблема не возникает

## Причина
Проблема была связана с порядком выполнения в Django:
1. Форма авторизации отправляется (POST запрос)
2. `CustomLoginView.form_valid()` выполняется успешно
3. Пользователь авторизуется через `auth_login()`
4. После этого Django middleware проверяет CSRF токен
5. На мобильных устройствах CSRF проверка иногда не проходит (из-за особенностей обработки cookies в мобильных браузерах)
6. Показывается страница ошибки 403, хотя пользователь уже авторизован

## Решение
Модифицирован обработчик `csrf_failure_view` в `/opt/pearls-site-django/myproject/apps/myapp/views.py`:

```python
def csrf_failure_view(request, reason=""):
    """
    Кастомная страница ошибки CSRF.
    
    Если пользователь уже авторизован, перенаправляем его на главную страницу.
    Это решает проблему на мобильных устройствах, где CSRF ошибка 
    может возникать после успешной авторизации.
    """
    import logging
    logger = logging.getLogger('django')
    
    if request.user.is_authenticated:
        # Логируем для мониторинга проблем с CSRF на мобильных устройствах
        logger.warning(
            f"CSRF error for authenticated user {request.user.email}. "
            f"Redirecting to home. Reason: {reason}. "
            f"User-Agent: {request.META.get('HTTP_USER_AGENT', 'Unknown')[:100]}"
        )
        # Перенаправляем авторизованного пользователя на главную страницу
        return redirect('home')
    
    # Для неавторизованных пользователей показываем страницу ошибки
    logger.warning(
        f"CSRF error for anonymous user. Reason: {reason}. "
        f"Path: {request.path}. "
        f"User-Agent: {request.META.get('HTTP_USER_AGENT', 'Unknown')[:100]}"
    )
    return render(request, '403_csrf.html', status=403)
```

## Что изменилось
1. **Проверка аутентификации**: Добавлена проверка `request.user.is_authenticated`
2. **Автоматический редирект**: Если пользователь уже авторизован, он автоматически перенаправляется на главную страницу
3. **Логирование**: Все случаи CSRF ошибок логируются для мониторинга с указанием User-Agent (для выявления проблемных браузеров)

## Результат
- ✅ Пользователь успешно авторизуется с мобильного устройства
- ✅ Не видит ошибку CSRF после авторизации
- ✅ Автоматически перенаправляется на главную страницу
- ✅ Проблема логируется для мониторинга
- ✅ Для неавторизованных пользователей страница ошибки CSRF по-прежнему показывается

## Мониторинг
Все случаи CSRF ошибок теперь логируются в журнал Django. Можно отслеживать:
- Частоту возникновения ошибок
- Типы устройств/браузеров, на которых возникают проблемы
- Email пользователей, у которых возникают проблемы

## Дополнительные настройки CSRF
В `settings/prod.py` уже настроены оптимальные параметры:
```python
CSRF_TRUSTED_ORIGINS = [
    'https://lc.smileterritory.ru',
    'https://www.lc.smileterritory.ru',
]
CSRF_COOKIE_SECURE = True
CSRF_COOKIE_HTTPONLY = False  # Позволяет JavaScript читать CSRF токен
CSRF_COOKIE_SAMESITE = 'Lax'  # Более мягкая политика
CSRF_USE_SESSIONS = False  # Используем cookies
```

## Безопасность
Решение не снижает уровень безопасности:
- CSRF защита остается активной
- Неавторизованные пользователи по-прежнему видят ошибку
- Авторизованные пользователи просто перенаправляются вместо показа ошибки
- Все случаи логируются для аудита
